# FR5 + ZED X 数据录制（SIO_SLAM 机械臂真值）

> 脚本的正本在 Box 的 `~/ROBOT/fr5_record/`，本仓库是笔记本上的备份，用 `.\sync_from_box.ps1` 从 Box 拉取。
> 实验过程、发现和问题处理见 [实验记录.md](实验记录.md)。

## 1. 目标

用 FAIRINO FR5 机械臂带着 ZED X 做已知运动，同时录制双目图像、ZED 机身 IMU 和机械臂状态，离线算出相机位姿真值，供 [SIO_SLAM](https://github.com/lihongliang0203/SIO_SLAM) 评估。

- **第一批 6 条录制**：相机始终水平朝前，每条只沿一个方向做纯平移：前进、后退、右移、左移、上升、下降。默认速度 0.05 m/s，行程 300 mm。
- **第二批 6 条录制（准备中）**：绕左目光心的单轴纯旋转，5 °/s：向左 / 向右偏航 10°，向上 / 向下俯仰 30°，向左 / 向右横滚 30°（和俯仰一样）。中心朝向都取在左右两扇玻璃窗中间（偏航 −2.25°、俯仰 −5°、横滚 −2°，负为向右），全程（含同步摆动）画面离任何玻璃至少 1°。
- **正式录制前先验证两件事**：(1) 时间同步；(2) 真值，用固定的标定板检验。标定板只在验证录制中出现，正式录制时撤掉。
- **相机真值**：`base_T_camera(t) = base_T_flange(t) · flange_T_left_camera`。手眼外参来自标定仓库 s003 的结果（`scripts/handeye_s003_result.json`），前提是相机安装之后没有动过。

## 3. 算法

### 3.1 相机真值

机械臂状态以约 100 Hz 推送法兰位姿（20004 端口）。每张图像在其曝光中心时刻插值法兰位姿（位置线性插值，姿态用 SLERP），再乘手眼外参得到左目相机在 FR5 基坐标系下的位姿。超出机械臂数据范围、或两侧状态包间隔超过 30 ms（丢包）的帧不输出真值；带机械臂错误码的帧会在 `groundtruth_images.csv` 中标记出来；时间戳重复的帧（ZED 偶尔把同一帧抓两次）只保留第一张。

真值里加了两项由标定板验证（3.3）得到的修正：
- **时间**：取真值的时刻再晚 4.27 ms（`TIME_CORRECTION_MS`）。
- **行程**：法兰平移沿本条录制的运动方向、相对路径起点放大（`TRAVEL_SCALE`）：right / left / up / down 为 1.0070，forward / backward 为 1.0015。录制方向和路径两端从 `motion_log.json` 读取；不是平移录制（如 sync-test）就不缩放。

同时输出一份不加这两项修正的真值，用于对照。

### 3.2 时间同步

涉及三个时钟：ZED 的图像和 IMU 时间戳本来就是 Box 系统时间；机械臂状态包带的是控制器时间，没有同步，比 Box 快约 125 s，漂移约 200 ppm；另外还有各环节未知的固定延迟。所有数据统一换算到 Box 系统时间。

1. **状态包接收**：录制程序独占 20004 连接，每包到达时记下 Box 的系统时间和单调时钟，停止时一次写盘。接收缓冲区设为 2 MB（约 8 s 的数据），即使同一进程里的计算一时占住 Python，控制器也不会因为发不出去而断开连接。
2. **控制器时钟换算**：每 2 s 取“到达时间 − 控制器时间”的最小值（延迟最小、最接近真实的那些包），对这些下包络点做直线拟合，得到偏差和漂移。每条录制单独拟合。
3. **剩余时间差 Δt**：把 ZED 陀螺仪的角速度大小（用静止段估出零偏后扣除）和由法兰姿态差分得到的角速度大小做互相关。为此每条录制的开头和结尾都有同步摆动：绕过相机光心的竖直轴 ±10°，20 °/s，来回 2 次，相机保持水平。前 40% 和后 40% 的数据还会分别估一次 Δt，两者相差超过 2 ms 就报警。
4. **曝光中心**：ZED 的图像时间戳不在曝光中间。对每一帧，取它前后半帧内 `image_sync_trigger=1` 的 IMU 样本（曝光期间采到的样本），用最早和最晚样本的中点减去图像时间戳，再用中位数绝对偏差剔除离群帧，得到曝光中心相对时间戳的偏差（实测约 −3.5 ms），真值在曝光中心取。输出文件里仍写图像原来的时间戳。IMU 每 5 ms 一个样本，这个估计最多有约 ±0.8 ms 的量化偏差。

**结果**

- 合成数据：恢复出 200.4 ppm 的漂移；真值位置误差 RMS 0.012 mm，转角误差 RMS 0.0066°。
- 全速 sync-test 4 次（每次约 30 s）：

  | 录制 | Δt (ms) | 互相关峰值 | 前后段差 (ms) | 单次拟合漂移 (ppm) | 曝光中心 (ms) |
  |---|---|---|---|---|---|
  | 161111 | +2.11 | 0.9988 | 0.08 | 160.0 | −3.59 |
  | 161424 | +1.99 | 0.9992 | 0.64 | 200.7 | −3.52 |
  | 161510 | +2.81 | 0.9989 | 1.20 | 209.1 | −3.39 |
  | 161611 | +3.22 | 0.9992 | 0.47 | 204.9 | −3.50 |

- 每次录制内部，前后段差 ≤ 1.2 ms。跨录制看，“时钟偏差 + Δt”（控制器时间到相机时间的总换算）在 5 分钟内落在同一条 198.7 ppm 的漂移直线上，残差 ≤ 0.24 ms。所以各次 Δt 的差别只是时钟拟合和 Δt 之间的分配不同。
- 1 ms 的时间误差，在 50 mm/s 平移时相当于 0.05 mm，在 20 °/s 转动时相当于 0.02°。
- 上述检验只能说明同步是自洽的，查不出一个固定的整体偏移。标定板验证（3.3）发现真值整体比图像晚约 4.3 ms。

### 3.3 真值验证（标定板）

标定板（Kalibr Aprilgrid，6×6 个 tag，每个 55 mm）固定放在相机前方约 1 m 处。每张左目图检测标定板，用 PnP 求出 `camera_T_board`（先 IPPE 再 LM 细化；内参用 s003 图像重标的 `scripts/camera_s003_refit.yaml`，见下面“重标焦距”；至少 8 个 tag，重投影 RMS ≤ 1 px）。再乘上真值得到 `base_T_board`。真值准确的话，`base_T_board` 应该始终不变。

- **重复性**：同一位姿的不同静止段之间，标定板位姿应该相同。
- **空间误差**：平移（或旋转）前后两个静止段之间的差，分解到起点相机系（x 右、y 下、z 前）。静止帧按时间间隔、相机位置（5 mm）和相机姿态（1°）分组。
- **转角对照**（旋转录制）：真值给出的相机转动，和从两组静止帧的标定板姿态（PnP）算出的相机转动比较。标定板不动，后者和机械臂无关。两者之差就是残差转动，转角之比对应平移录制的行程放大。
  - PnP 单帧姿态的精度约 0.03°，转 10° 时转角比例只能测到约 ±0.3%，转 30° 时约 ±0.1%。
  - 标定板位置差更精确：相机多转 ε，距离 d 处的标定板横向差约 ε·d（1 m 处 0.1° 约 1.75 mm）。不过光心（手眼平移）有误差时，相机转动也会让光心移动，同样表现为位置差。
- **时间扫描**：把真值时间整体平移 δ，找使摆动帧最一致的 δ。只用在静止位姿附近（20 mm、12° 以内）做同步摆动的帧，每帧和最近的静止段比较；有 `motion_log.json` 时再按段名去掉平移段和旋转段的帧。这样平移或旋转带来的空间误差不会混进来。这个检验和陀螺仪互相关完全独立，δ 应接近 0。
- **误差分解**：right / up / forward 三个方向互相正交，平移后标定板的位置差和姿态差在三个方向上表现不同。
  - 机械臂行程的尺度误差，产生沿运动方向的差。用的是实测的标定板尺寸，横向位置差与焦距无关（一阶近似）。
  - 焦距误差：主要放大深度；标定板偏离光轴时，还会使 PnP 估出的标定板倾角产生偏差。
  - 主点偏差：深度变化时（forward）产生横向差。
  - 手眼转角误差 θ：产生垂直于运动方向的差 −θ × m。
  - 手眼平移误差：在差分中抵消。
- **双目复核**：用左右目同一角点的视差做三角化，尺度来自出厂基线（120.094 mm），与标定板尺寸无关。
  - 横向位移 = (u − cx) · B / d，和焦距无关。
  - 视差的固定偏差（出厂双目校正有漂移时出现）会让尺度误差与距离成正比。这个偏差由“双目测得的标定板尺寸随距离的变化”估出，不需要用到标定板的绝对尺寸。
- **重标焦距**：深度测量（单目和双目）都与焦距成正比，所以 forward 方向要先确定焦距。用 s003 标定拍的 25 张图像：
  - 只用标定板角点做相机标定（张正友法，固定无畸变）。图像中标定板倾角 10–37°，结果与机械臂和标定板尺寸都无关；
  - 再加上机械臂位姿、手眼外参和机械臂各轴尺度做联合拟合，作为交叉验证。
  - 同步摆动（只有 ±10° 偏航）里，焦距和手眼外参沿光轴的平移几乎分不开，不用它定焦距。
- 合成数据测试：
  - 平移：人为让真值晚 4 ms，从图像中找回 +4.0 ms；三个静止位置之间的差 0.03 mm。
  - 旋转（光心不动，转 10°）：真值少报 1%（实际 10.1°），同时晚 4 ms。转角对照得 +0.77%（PnP 姿态精度所限），标定板横向差 1.76 mm（预期 1.75 mm），时间仍找回 +4.0 ms。

**结果**（标定板距离 1.0–1.3 m，三条录制每帧都检测到标定板，重投影中位 0.13 px）。下表是加修正之前、用出厂内参的结果，加修正后的结果见本节最后。

| 检查 | right | up | forward |
|---|---|---|---|
| 重复性（同一位置的静止段之间） | 0.02–0.03 mm | 0.02–0.06 mm | 0.02–0.15 mm |
| 平移 300 mm 后标定板差（起点相机系，mm） | (−2.05, −1.97, +0.14) | (−0.56, +2.04, +1.46) | (+2.88, +2.82, +0.38) |
| 平移后标定板姿态差 | 0.09° | 0.14° | 0.06° |
| 时间扫描 δ | +3.97 ms | +4.41 ms | +4.44 ms |
| 摆动帧离散（δ = 0 → 最佳 δ） | 1.20 → 0.32 mm | 1.31 → 0.31 mm | 1.33 → 0.37 mm |

- **时间**：**真值比图像晚 4.27 ms**（三条平均，标准差 0.26 ms；12 个位置分别在 +3.7 到 +4.9 ms 之间）。
  - 这是陀螺仪和图像之间的固定偏移，不是时钟拟合的问题。依据：“Δt + δ”在三条之间相差 1.0 ms，而 δ 只差 0.5 ms。
  - 偏移来源有两种可能：ZED 陀螺仪输出滞后（内部滤波）；或者由 `image_sync_trigger` 估出的曝光中心（−3.5 ms）有偏差。曝光固定为 10 ms 时两者效果相同，改变曝光后要重新验证。
  - 修正已加入 `fr5_groundtruth.py`（3.1）。加修正后重算这三条，时间扫描得到 −0.30 / +0.13 / +0.17 ms。
- **空间**：下表是机械臂实际行程相对控制器报告值的偏差，正值表示实际走得更长。

  | 方向 | 单目（以标定板 412.5 mm 为尺度） | 双目（以出厂基线为尺度，扣除视差偏差） | 结论 |
  |---|---|---|---|
  | right | +0.68% | +0.66 到 +0.73% | **实际行程长约 0.7%** |
  | up | +0.67% | +0.68 到 +0.75% | **实际行程长约 0.7%** |
  | forward | +0.13%（按 fx = 736.2 px 换算） | +0.16%（同左） | **实际行程长约 0.15%** |

  - **right / up**：
    - 标定板尺寸已用钢尺复核为 412.5 mm；出厂基线与它一致到 0.07%。
    - 这两个互相独立的长度基准都与机械臂差约 0.7%（300 mm 约差 2 mm）。
    - left / down 走的是同一段路径，误差相同。
    - s003 手眼标定的尺度诊断（标定板尺度 0.9948）指向同一个方向。
  - **焦距**：
    - 只用图像标定：fx = 736.23 px，cx 987.72，cy 555.14，重投影 0.112 px；逐一去掉每张图后 fx 在 736.08–736.33 之间。
    - 加机械臂的联合拟合：fx = 736.07 ± 0.21 px。
    - 两种方法一致，比出厂值 734.46 px 大 0.23%。fx = 740 px 被排除。
    - forward 方向据此换算为 +0.13 到 +0.16%（backward 走同一段路径，误差相同）。
  - **双目校正有漂移**：左右目同一角点有 0.4 px 的上下错位；双目测得的标定板尺寸比实际小 0.45%，偏差与距离成正比（0.89 m 处 0.9965，1.19 m 处 0.9951）。这符合约 0.37 px 的视差固定偏差。录制时关了自标定，用的是出厂校正。
  - 只做三方向联合拟合（内参 + 每方向行程 + 手眼转角，残差 0.71 mm）时曾给出 fx ≈ 740 px，靠的是二阶效应，已被上面的焦距标定否定。
  - **姿态**：平移后标定板姿态变化 0.05–0.14°，联合拟合后仍剩 0.04°（RMS），可能是机械臂平移时的真实转动。
  - 手眼转角误差在纯平移时只给真值姿态带来一个固定偏差，不影响真值位置。

|---|---|---|---|

| 残差转动大小 | 0.05° | 0.18° | 0.10° |
| 转前转后标定板差 | 0.44 mm | 3.85 mm | 1.0 mm |

| 摆动帧离散（最佳 δ） | 0.26 mm | 0.78 mm | 0.24 mm |

- 俯仰的误差两次录制一致（另一次 +0.45%、3.87 mm），是系统性的。标定板差几乎全由残差转动造成（0.18° × 1.12 m ≈ 3.6 mm），光心位置没问题，偏的是真值的姿态：转满 30° 时约 0.18°，其中沿俯仰轴 0.11°（机械臂报的转角比实际少约 0.4%）。
- 不是相机内参的问题：用 s003 图像放开 fy 重标，fy/fx − 1 = +0.027%；放开径向畸变 k1 = +0.0005（角点覆盖到离光轴 53°）。要解释俯仰的误差需要 fy 差 0.4% 或 k1 ≈ 0.05。
- 原因应该和平移录制垂直方向剩下的 1.5–3.7 mm 一样，是机械臂绝对精度和手眼外参的误差。俯仰要转 J2–J4，偏航主要转 J5，横滚主要转 J6。
- 时间扫描在三种转动上差 ±2 ms：图像对陀螺仪在三条里都是 0 ms（`frame_lag_check.py`），差别来自陀螺仪和机械臂的对齐，随转动方向不同。20 °/s 时 2 ms 约 0.04°（1 m 处 0.7 mm），主旋转段（5 °/s）只有约 0.01°。
- **图像偶尔整条晚一帧**：14:17 第一次录的俯仰，图像内容整条比时间戳晚一帧（+66 ms），标定板运动帧偏差最大 29 mm。用 `frame_lag_check.py` 能发现（不需要标定板，也不用机械臂数据）：同步摆动时相邻两帧的特征点（LK 光流）按纯旋转拟合转角，得到图像看到的角速度大小，和陀螺仪在同一帧间隔内的平均角速度大小比较，找图像相对时间戳的延迟。合成数据测试：对齐时 0.0 ms，晚一帧时 +66.7 ms。10-10～10-13 的 12 条正常录制（含 10-12 的 6 条正式录制）在 −0.2～+0.5 ms，晚一帧的那条 +66.2 ms。

### 3.4 运动与速度

- **轨迹**：所有目标点先换算成相机位姿，再除以手眼外参得到法兰目标。MoveL 以非阻塞方式下发，到位由状态包判断。录制前用控制器逆解沿路径每 10 mm / 2° 检查一次：有解、关节在允许范围内、不跳到另一组逆解、相机不低于下限。
- **速度**：这台控制器拒绝 MoveL 的物理速度模式（mm/s），所以用百分比速度。百分比和实际速度的换算由 `speed-test` 实测：平移和摆动各在两个速度下测，并检查是否成正比。
- **旋转**：MoveL 让法兰走直线、姿态匀速插值；绕光心转时光心会在半路鼓出去（按手眼外参算，转 30° 时偏航 3.9 mm、俯仰 4.2 mm）。所以旋转段用 MoveC：经过转了一半的姿态，法兰绕旋转轴走圆，光心不动。逆解检查沿这条圆弧采样，同时求出中间点的关节角。这台控制器上 MoveC 即使 `blendR=0` 也要走完才返回（10-12 实测），所以脚本在后台线程里调用它，主线程照常逐包监视和保护。同步摆动仍用 MoveL（20° 的一段中途偏离约 1.8 mm，只用来对时间）。
- **同步摆动**：平移录制和 sync-test 绕相机自身的竖直轴两边摆 ±10°。旋转录制绕本条的转轴、只往旋转范围内侧摆（开头顺着旋转方向，结尾逆着；真值只用角速度大小），所以摆动不会让画面扫出旋转本身的范围。总转角小于摆动幅度（10°）时，摆动会从另一头多出来。
- **不拍到玻璃**：两边都有玻璃窗（只管玻璃窗，房间远处的展示柜不算）。10-13 用旋转演练的 32 张静止帧（光心都在起点光心）按机械臂位姿拼成方位角 / 仰角全景图，量出玻璃的位置（相对起点水平朝向，向左为正）：
  - 左窗玻璃在 +57.4° 以左（再往里到 +55.5° 是窗框），上沿仰角 +27.3°，下面被压力机挡住；
  - 右窗玻璃在柱子边缘 −60.3° 以右，在远处，仰角约 −6.5～+4°；
  - 没拍到的地方（+76° 以左、−87° 以右）按全是玻璃处理。

  这些区域写在 `GLASS_REGIONS` 里。`plan` 和 `record` 沿每条旋转录制的路径每 0.5° 取一个相机姿态，算画面四条边离玻璃区域的角距离，小于 `GLASS_MARGIN_DEG`（1°，画面左右边缘约 35 px）就拒绝。量出的边界投影回原图，和朝向 −10° 时右边缘露出的约 45 px 窗户、09:49 正对右窗时的窗户边缘都对得上；画面角落附近这个角距离偏小，结果偏保守。
  - 画面的水平视场约 105°（主点不在正中：左半 53.3°、右半 51.7°），两扇窗之间只剩约 12° 可以转，所以偏航只能 10°；俯仰、横滚时画面角落扫得更远，但只在玻璃以外的仰角上，可以转得更多。
  - 平移录制光心在动，不在这个检查范围内；它们的同步摆动转到 +10° 时，画面左边缘露出一窄条左窗。
- **朝向和关节**：起点处 J5 约 −45°。
  - **偏航**基本只转 J5（每 1° 约 1.2–1.3°）。
  - **俯仰**时 J4 轴和相机 x 轴不平行，要靠 J6 抵消横滚分量：J6 约等于俯仰角 × cot|J5|。在起点处 J5 约 −45°，俯仰 1° J6 也要转约 1°；向右转到 J5 约 −90° 时 J6 才不用动，但那个朝向正对右窗。
  - **横滚**绕光轴，基本只转 J6（相机光轴和法兰 z 轴差约 1.5°），J1–J3 移动法兰让光心不动（法兰离光轴约 93 mm）。用户 10-13 目测：在起点姿态下 J6 转 60° 以内不会碰；按用户要求再保守 10°，J6 限位取 ±50°。
  - **结果**（10-13 用控制器逆解沿路径每 1° 算出）：
    - 偏航 10°，中心 −2.25°，全程朝向 −7.2～+2.7°，离玻璃 1.22°；J4 −121～−117°，J5 −53.4～−41.6°，J6 不动；
    - 俯仰 30°，中心 −5°，离玻璃 1.99°；J4 −146.7～−90.4°（限位 −154～−87°），J5 −53.5～−50.5°，J6 −11.9～+11.0°；
    - 横滚 30°，中心 −2°，离玻璃 2.94°；J6 −15.4～+15.3°，J4、J5 几乎不动（10-13 先按 20°、J6 ±10.3° 低速演练过）。转多大都不会拍到玻璃（转到 ±45° 时离玻璃仍有约 2.1°），上限由 J6 决定：总转角 90° 时 J6 −46.0～+45.8°，在 ±50° 以内。
    - 偏航不能再大：11° 时离玻璃只剩 0.77°。俯仰 40° 时 J4 到 −160°，超出标定走过的范围。
- **运动模糊**：平移 `blur = fx · v · T / Z`，其中 fx ≈ 735 px，默认 0.05 m/s、曝光 10 ms 时 1 m 处为 0.37 px；旋转 `blur = fx · ω · T`，和景深无关，5 °/s 时为 0.64 px。
- **保护**：运动中实时测法兰线速度和角速度，超过预期 1.5 倍 + 5 mm/s（角速度 + 2 °/s）就停，以转动为主的段（旋转、同步摆动）只查角速度，因为起步时控制器会先平移约 1 mm，线速度会误报；MoveC 时光心偏离旋转中心超过 2 mm 就停；超过 2 s 没有新状态就停；没到位又 5 s 不动就停。停止时用新的 XML-RPC 连接发 StopMotion。Ctrl+C、SSH 断开或被终止时，先停机械臂，再正常停相机、保存数据。
- **关节范围**：腕部 J4、J5 限制在这套末端装置已经安全走过的范围内（再往外 Box 可能碰到腕部，见标定仓库 README 6.4 / 6.7）。10-10、10-12 的录制实测 J4 −151～−99°、J5 −69.5～−22.1°、J6 一直是 0，各留约 3° 余量，即 J4 下限 −154°、J5 −72～−19°；俯仰 30° 要 J4 到 −90°，按标定走过的范围（J4 −154～−77°）放宽到 J4 上限 −87°；J6 为起点 ±50°（用户目测 ±60° 内不会碰，再留 10°）。机械臂当前就在范围外时（例如上次停在别的朝向），移到起点的那一段可以从范围外往回走，但越界只能越来越小，终点必须回到范围内；录制段一律严格检查。

**结果**

- 1% = 平移 1.001 mm/s、摆动 0.347 °/s，WebApp 的 10% 也作用在 SDK 指令上。平移 50 mm/s 需要 49.97%，摆动 20 °/s 需要 57.59%；最高能到 100 mm/s、36 °/s。
- 两个速度之间的换算系数：平移相差 −0.3%，摆动相差 −3.6%。
- 实测平移 49.9–50.0 mm/s，巡航段速度波动 2.5–3.4%；同步摆动 19.7–20.8 °/s。
- 按 Ctrl+C 后，机械臂在 0.133 s 内停下。

## 5. 使用流程

### 5.1 安装（Box，一次性）

1. **SDK**：把第 2 节那个提交的 `linux/fairino/Robot.py` 放到 `~/.local/lib/python3.10/site-packages/fairino/`，再建一个空的 `__init__.py`，用 `sha256sum` 核对。
2. **zed_record**：源码在 `~/ROBOT/zed_imu/`，打上 `zed_record/zed_record.patch` 后编译：
   ```bash
   cd ~/ROBOT/zed_imu/build && make -j4 zed_record
   ```
3. **脚本**：把 `scripts/` 里的文件放到 Box 的 `~/ROBOT/fr5_record/`。
4. **WebApp**：自动模式的速度百分比不能是 0，并且要和 `WEBAPP_SPEED_PCT` 一致（当前为 10）。

### 5.2 录制

在 Box 自己的终端里运行，人站在机械臂旁边，手边有急停。每次运动前脚本都会列出计划（每段的速度百分比、预计速度和时长），输入 `yes` 才会动。

```bash
cd ~/ROBOT/fr5_record
python3 run_session.py set-start               # 读当前位姿，算出相机水平的起点并保存（不动）
python3 run_session.py plan                    # 空跑：检查全部录制和 sync-test 的路径（不动）；也可只列几条，如 plan yaw_left pitch_up
python3 run_session.py goto-start --scale 0.25 # 低速移到起点
python3 run_session.py speed-test              # 速度标定（不开相机）；改了 WebApp 速度百分比或 ACCEL_PCT 要重跑
python3 run_session.py sync-test               # 时间同步验证（只做同步摆动）
python3 run_session.py movec-test              # MoveC 探测（不开相机）：MoveC 和 MoveL 各绕光心竖直轴转 ±10°，对照光心偏离和速度
python3 run_session.py record forward          # 正式录制，另有 backward / right / left / up / down
python3 run_session.py record yaw_left         # 旋转录制，另有 yaw_right / pitch_up / pitch_down / roll_left / roll_right
```

- **每条录制的结构**：静止 5 s → 同步摆动 → 静止 3 s → 单向平移 300 mm（或绕光心旋转）→ 静止 3 s → 同步摆动 → 静止 5 s。平移约 32 s、0.4 GB；旋转 24–28 s、0.3 GB。结束后自动计算真值，并打印 Δt 和前后段差；旋转录制还打印实测角速度、转角和光心最大偏离。
- **zed_record 没有正常结束**（返回码不为 0、停止前自己退出、或没写 `time_meta.txt`）时，最后打印“录制失败”，退出码为 1，`motion_log.json` 的 `error` 写明原因。这时 `img_timeline.csv`、`zed_imu.csv` 可能缺结尾，这条要重录。
- **每段运动结束后**打印实测的法兰线速度、角速度和用时，可以和计划对照。
- `--scale 0.25`：按比例降速，用于首次低速演练。这时同步摆动只有 5 °/s，算不出 Δt，数据不用。
- **第一次跑新的转动**（俯仰的单侧摆动、横滚，或加大 `ROLL_DEG`）：先用 `--scale 0.25` 演练，旁边有人盯着 Box 和腕部之间的间隙以及线缆。
- **画面里不能有人**，也不能拍到玻璃；旋转录制由玻璃窗检查保证（3.4）。
- `--tag board`：给录制目录名加后缀（如 `…_right_board/`），用来区分验证录制和正式录制。
- 按 Ctrl+C 或 SSH 断开：先停机械臂，再正常停相机，保存已录的数据。断开后的输出写进录制目录里的 `run_session.log`。
- **录完检查图像是否晚一帧**：每条录制（正式录制和标定板验证录制都要）拷到笔记本后，在 `scripts/` 下用标定仓库的 venv 运行 `python -B frame_lag_check.py <save_data 目录> ...`（可以一次给多个），报“晚约 1 帧”的重录。

### 5.3 标定板真值验证

1. 用标定时的那块 Aprilgrid，竖直放在起点相机正前方约 1 m 处，中心大致和相机同高，固定牢。
2. 短暂打开 ZED Explorer，确认标定板完整地在画面中间附近，然后关掉。
3. 在 Box 上录三个平移方向和三种旋转（反方向走的是同一段路径，不用重复录）：
   ```bash
   python3 run_session.py record right --tag board
   python3 run_session.py record up --tag board
   python3 run_session.py record forward --tag board
   python3 run_session.py record yaw_left --tag board
   python3 run_session.py record pitch_up --tag board
   python3 run_session.py record roll_right --tag board
   ```
   旋转录制的中心朝向在起点右侧 2–5°，标定板放在正前方即可，全程都在画面里：标定板约 ±12°，俯仰 ±15° 时离画面上下边缘还有约 9°。
4. 把每条录制拷到笔记本的 `data/board_check/<录制名>/`。`save_data/right/` 不用拷，其余都拷：验证只用左目，而带上 `fr5_state.csv`、`zed_imu.csv` 以后可以在笔记本上重算真值。然后在 `scripts/` 下用标定仓库的 venv 先检查图像是否晚一帧，再做标定板检查：
   ```bash
   python -B frame_lag_check.py ..\data\board_check\<录制名>\save_data
   python -B gt_board_check.py ..\data\board_check\<录制名>\save_data
   ```

### 5.4 注意事项

- **图像可能整条晚一帧**（3.3）：原因在 ZED SDK 内部，日志看不出来。每条录制拷到笔记本后都要运行 `frame_lag_check.py`，报异常（退出码 1）的重录。
- **20004 只能有一个连接**：录制时不要另开 `Robot.RPC(...)`，运动脚本必须用 `StateRecorder.open_rpc()`。
- **录制进程里不要做长时间的 Python 计算**：真值计算等重活放在录制停止之后。
- **不要调用 SDK 的 `LoggerInit()`**：它会持续往磁盘写日志。
- **相机同一时间只能被一个程序打开**：录制前关掉 ZED Explorer、Depth Viewer、`zed_snapshot.py`。
- **Box 的 WiFi 会断**：运动和录制在 Box 本机终端运行（Box 没有 tmux / screen）。拷大量数据时也常掉线，先在 Box 上打 tar 包再限速拷（如 `scp -l 24000`，约 3 MB/s），拷完核对 sha256。
- **开机预热**：Box 重启后相机有冷热漂移，预热 30 分钟以上再录真值数据。重启后的头几分钟系统时间还在对时调整，时钟拟合残差可能超过 1 ms（10-12 实测对真值影响 ≤ 0.03 mm）；预热完再录，这个问题也一起避开。
- **场景**：画面里不要有人走动；数据如果要公开，先征得画面里的人同意。
- **错误码**：SDK 返回的正数错误码来自控制器，查 FAIRINO 官方“错误码对照表”。例如 172 表示运动速度不能为 0，182 / 183 表示给定的物理速度 / 加速度超限。

## 6. 输出数据

每条录制一个目录（Box 上）：

```text
~/ROBOT/sessions/YYYYmmdd_HHMMSS_<名称>[_<tag>]/
├─ zed_record.log            zed_record 的输出（结束时一次写入）
├─ run_session.log           仅在 SSH 断开 / 被终止时才有
└─ save_data/
   ├─ left/  right/          <ZED 时间戳 ms>.jpg（校正后，JPEG）
   ├─ img_timeline.csv       每帧：图像时间戳、对应 IMU 时间戳、文件名
   ├─ zed_imu.csv            机身 IMU 全部样本（约 200 Hz），含 image_sync_trigger
   ├─ time_meta.txt          相机设置，含第 30 帧读回的实际曝光和增益
   ├─ fr5_state.csv          机械臂状态（约 100 Hz）：Box 时间、控制器时间、关节、法兰位姿、错误码等
   ├─ fr5_meta.json          丢包、断线、时钟跳变、接收缓冲区大小等
   ├─ motion_log.json        每段指令：时间、速度百分比、预计速度、实测速度；平移段速度和波动；所用速度标定；
   │                         旋转录制还有 MoveC 的中间点、转轴、光心偏离，以及旋转段的角速度汇总（rotate_speed）；
   │                         zed_record 的返回码；录制失败时 error 写明原因（运动中止，或 zed_record 没有正常结束）
   ├─ groundtruth_tum.txt    每张图一行：timestamp tx ty tz qx qy qz qw（Unix 秒、米），左目在 FR5 基坐标系下（已加修正）
   ├─ groundtruth_tum_uncorrected.txt  同上，不加时间修正和行程放大（对照用）
   ├─ groundtruth_arm_rate_tum.txt   机械臂每个状态包一行，格式同上（已加修正）
   ├─ groundtruth_images.csv         每张图的真值和标记（ok / duplicate / outside / gap / robot_error）
   └─ groundtruth_report.json        时钟拟合、Δt、前后段差、曝光中心、时间修正、行程放大、警告
```

笔记本上的副本放在 `data/` 下（不进 git）：正式录制在 `data/recordings/<录制名>/`（10-12 的 6 条，含左右目，2.4 GB；给数据使用者的说明是同目录的 `使用说明.md`，标定文件在 `calib/`），标定板验证录制在 `data/board_check/<录制名>/`。

真值可以单独重算：

```bash
python3 fr5_groundtruth.py <save_data 目录> --handeye handeye_s003_result.json
```

`gt_board_check.py` 在 `save_data` 目录里输出：

- `board_check_report.json`：重复性、静止组之间的差（分解到起点相机系）、按位置分组的时间扫描。
- `board_check_frames.csv`：每帧的 tag 数、重投影误差、相机速度、标定板中心和偏差。

`frame_lag_check.py` 在 `save_data` 目录里输出 `frame_lag_report.json`：图像相对时间戳的延迟（ms，正值为图像晚）、折合几帧、是否正常、用了多少对相邻帧，以及 0 ms / 最佳 / 晚一帧三处图像和陀螺仪角速度之差的 RMS 和整条扫描曲线。
